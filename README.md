面向 SillyTavern 文字冒险 / 角色扮演的结构化记忆扩展：**当前状态台账 + 双时态历史 + 秘密知情约束**。

- 类型：SillyTavern 正式扩展（manifest + 前端模块）
- 依赖：无第三方 npm 依赖

## 0. 设计底线（改代码前先读）

这一节是这个扩展的产品需求与边界。改动前先对照这里，避免功能越加越多，本职工作越做越偏。

### 0.1 要解决的两件事

1. **当前状态记住**：关键状态离开叙事模型的上下文窗口后，插件仍能把「现在」带回注入；主角拿了什么、丢了什么、欠了谁、身上有什么伤，仍然查得到。
2. **秘密隔离**：NPC 只能知道自己该知道的事，不能因为台账里有，就随口说出主角的底牌。

**不解决「发生过什么」**：事件记忆交给酒馆原生上下文与向量召回。插件不建事件台账、不做旧事召回，也不提醒漏记大事。做错比不做更伤代入感，所以这条边界是刻意画出来的。

事实隔离是本职工作，其余功能都不能破坏它。

这个扩展服务的是**单人主角的 AI 角色扮演**，不是群像小说。所有 NPC 都为推进主角的剧情而存在，没有自己的生活线和独立秘密体系。因此隔离只保护一条边界：**主角的秘密不能被 NPC 随口说出或利用**；不需要反过来给每个 NPC 建立一套自己的秘密档案。

### 0.2 事实隔离的实现方式

隔离的手段是**在词条进入剧情时，明确告诉叙事者这条信息该被谁知晓**，而不是把词条从注入里删掉。

- 每条秘密带一个档位（主角级/亲密级/朋友级/公开级），角色的亲近程度决定默认能不能知道。秘密照常进入注入，移到【秘密知情】，写成 `亲密级；默认知情=…；默认不知情=…；怀疑=…；误以为…`；留在普通行里的秘密则带 `[K:…]`。
- **正文明确优先，正文沉默时档位兜底**：正文写明谁不知道/谁知道，就按正文，不要用台账反驳；正文没写时才按档位。档位要防两种错：① 旧事超出上下文，叙事者没看到，把明明知情的 NPC 写成不知道；② 叙事者看到了现场，但正文没写某个不知情 NPC 不知道，就顺口让他知道。所以在场/看到/沉默都不等于知情。
- 承诺保密不改变谁知道，只约束「会不会传出去」。只告诉某一个人时，`reveal` 会把档位放宽到该人所在档；同档其他人也会知道。这是档位级的精度代价。
- 只有两种情况会真正移除词条：一是冷词条（超出热窗口、无人在场、无关键词命中），只隐藏并计数，相关角色回来或被提到的，自动恢复；二是 token 预算不足，且秘密是最后才砍的部分。
- 隔离的对象是主角的信息边界，不是给 NPC 加独立档案。NPC 自身的境界、身份、关系对玩家公开，这是正确的；判断一条隔离是否必要，只看它会不会让 NPC 说出或利用主角不该被知道的事。
- 所以接入新条目时先问两件事：它进注入时带没带档位？它是不是被误删了？

### 0.3 需求清单

**A. 事实台账**
- 只记五类当前事实：状态、物品/金钱、关系、功法与神通、秘密/身份/承诺。
- 「谁拿了什么」以主角为准：主角持有什么、失去了什么、被谁拿走。NPC 的私人物品不需要单独建账。
- 每条都有生效时间、证据和置信度；采用双时态，编辑、删除、swipe、分支、检查点都能回放。
- 场景记录时间、天数、地点、在场者；状态变化能据此算出间隔。
- 不记天气、寒暄、点头、日常修炼、一次性动作，也不记事件。

**B. 认知隔离**
- 主角的所有可保密条目都支持 `access`（主角级/亲密级/朋友级/公开级）：字段、物品、关系、个人事实、功法、神通、顶层事实。
- 角色档位 ≥ 条目档位才算默认知情；`beliefs` 里的怀疑 / 误信不算知情。
- 正文明确写谁不知道/谁知道时，当前正文优先；正文没写才按档位。台账不记个人级知情例外。
- 注入给叙事者的是「谁知道、谁不知道」，不是「这条存不存在」。
- 玩家始终看到真相；状态栏不因隔离而隐藏主角自己的东西；NPC 自身信息对玩家公开，不做反向隐藏。
- 正文明确写某人知道了，就用 `reveal` 放宽到该人所在档；同档其他人也会知道。每次成功的 `reveal` 都会提醒用户。

**C. 长篇一致性**
- 不记事件：离散剧情交给酒馆原生上下文与向量召回；插件只保证当前状态和知情关系一致。
- 顶层的秘密事实会冷化，但相关角色在场、关键词命中或线索未了结时重新热起来；挂在角色身上的秘密（物品、关系、功法、神通、字段）常驻，避免主角自己的东西从剧情里消失。
- 未了结的人情、承诺、仇怨、悬案常驻（最多 6 条，其余只计数）。

**D. 注入与协作**
- 注入有预算；超预算时先砍离场名录，再砍非主角角色块，最后才砍秘密。
- 不接管酒馆的叙事请求，不改破限预设；提取走独立 API 配置，是否附带预设可开关；每轮 AI 回复后自动结算，超时控制在 20 秒级。
- 提取失败会区分拒绝、内容过滤、空正文、超时、鉴权、限流、网络与 JSON 不合规，在状态栏和 toast 提醒；同类失败 60 秒内只提示一次。

**E. 玩家主权**
- 不擅自改玩家的姓名、身世、灵根、体质和已经写出的经历。
- 不替玩家说话、做决定、表态，不替玩家做有分歧的选择。
- 旁白可以顺着玩家写出的动作扩展物理细节，以及自然发生的观察和过程，但不能借机改变局面。

**F. 用起来顺手**
- 状态栏只属于主角，开局就显示，含境界进度与外貌体型。
- 面板能查看台账、编辑 JSON、编辑档位、做健康检查、看版本日志、导入导出；换聊天数据不串。

### 0.4 明确不做

- 不写预设剧情、不列预设 NPC（那是世界书的事）。
- 不做向量库、RAG。
- 不自动推进剧情、不替玩家制造机缘。
- 不修改 SillyTavern 源码。
- 不维护、不测试修仙以外的题材预设：都市、科幻、悬疑、言情、自定义只是占位，留在代码里即可，不投入开发成本。

### 0.5 改动前自检

1. 新数据能不能被隔离？不能就是不合格。
2. 它进注入时带没带知情范围，会不会让 NPC 说出不该知道的秘密？
3. 这条隔离是在保护主角的信息边界，还是在不必要地给 NPC 建立独立档案？
4. 会不会把当前状态记错，或为了记剧情而新增事件类条目？
5. 会不会替玩家做决定、加设定？
6. 会不会挤占注入预算，或干扰叙事与破限？

## 1. 它解决什么问题

普通 SillyTavern 记忆主要依赖「聊天摘要 + 向量检索」：

- 摘要有损，物品、境界、关系等事实容易丢失；
- 向量按“相似”召回，问“主角现在什么境界”可能召回旧描写；
- 所有角色共享同一份上下文，NPC 容易知道他们不该知道的秘密。

本扩展把记忆改成**可查询、可校验、可编辑的事实台账**：

| 层 | 内容 | 取法 |
|---|---|---|
| 工作记忆 | 当前场景 | 最近对话 + 场景卡装配 |
| 语义记忆 | 角色状态/物品/关系 | 按角色 ID 直接取 |
| 情景记忆 | 不负责 | 交给 SillyTavern 原生上下文与向量检索 |
| 认知矩阵 | 谁知道哪些秘密/谁不知道/谁只是怀疑 | 按角色取认知清单 |
| 原文兜底 | 旧场景逐字引用 | 仍可交给 SillyTavern 的向量检索 |

## 3. 安装

### 方式一：Git 安装（推荐）

在 SillyTavern 的「扩展」面板里点「Install Extension」，填入：

```
https://github.com/fbsfyl/SillyTavern-FactLedger
```

或者手动克隆到扩展目录：

```bash
cd <SillyTavern 安装目录>/data/default-user/extensions
git clone https://github.com/fbsfyl/SillyTavern-FactLedger
```

### 方式二：手动拷贝

把整个 `SillyTavern-FactLedger` 文件夹放到：

```
<SillyTavern 安装目录>/data/default-user/extensions/SillyTavern-FactLedger
```

### 启用

然后在 SillyTavern 中：

1. 打开「扩展」面板，确认 **Fact Ledger (事实台账)** 已启用；
2. 刷新页面；
3. 扩展菜单出现「事实台账」，设置面板出现「事实台账 (Fact Ledger)」。

## 4. 配置

| 设置 | 默认 | 说明 |
|---|---|---|
| 启用台账 | 开 | 关闭后清空注入 |
| 自动结算间隔 | 1 | 每 N 条消息自动结算；`0` = 仅手动。每次只提取新消息 + 前 3 条上下文 |
| 主角状态栏 | 开 | 右下角只显示主角的紧凑面板 |
| 主角 | 空 = 第一个 main | 指定状态栏显示的角色 |
| 题材预设 | 修仙 | 修仙 / 都市 / 科幻 / 悬疑 / 言情 / 自定义 |
| 题材与字段提示 | 修仙提示 | 进入提取提示；选择预设自动填入，可手动修改 |
| 每回合注入叙事规则 | 开 | 与台账一起注入；关闭后只注入台账 |
| 叙事规则 | 修仙默认规则 | 插件侧规则：台账与知情约束；从题材预设自动填入，可手动修改 |
| 跟随当前连接 | 关 | 勾选后用当前聊天连接做提取；不勾选则使用指定的 Connection Manager profile |
| 提取连接配置 | 空 = 跟随当前选中 profile | 建议单独指定稳定、擅长 JSON 的模型 |
| 提取最大 token | 4096 | 27B 提取约 600–1200；思考型模型建议 8192 |
| 置信度阈值 | 0.7 | `≥0.7` 自动应用；`0.5–0.7` 进入待复核；`<0.5` 拒绝 |
| 注入 token 预算 | 3000 | 超出后按「其他角色 → 非主角角色块 → 未了结 → 秘密」裁剪；角色认知最后才删 |
| 注入位置 | 系统提示层 | 与主 system prompt 合并，兼容只接受首条 system 的模型 |
| 秘密知情约束 | 开 | 是否注入每个在场角色的认知清单；关闭后秘密内容仍注入，只是不再标「谁知情」 |
| 泄露检测 | 开 | 是否保存并使用提取模型返回的 `leaks` |

### 叙事规则（插件侧）

修仙预设内置一套**插件侧**规则：怎么读【事实台账】【秘密知情】【未了结】，以及秘密只能通过正文写明的途径被得知。首次安装会自动填入「叙事规则」，并随台账在每回合注入。

- 规则跟着插件走；换角色卡不需要重新配置。
- 角色卡自己的叙述规则（人称、玩家主权、节奏、NPC、文风）仍留在角色卡的系统提示词里，两边不重复。
- 切题材时，如果文本框为空、或仍是旧题材的默认规则，会自动换成新题材的默认规则；手动改过的内容不会被覆盖。
- 「恢复题材默认规则」可取回当前题材的默认规则。
- 规则和台账共用系统提示注入；关闭「启用台账」时，规则仍可单独注入，取决于「每回合注入叙事规则」。

### 题材预设与字段

默认是**修仙**，字段提示会进入提取提示，告诉模型该用哪些 `state` 字段。

| 预设 | 常用 state 字段 |
|---|---|
| 修仙（默认） | realm（境界）、technique（功法）、spiritRoot（灵根）、sect（宗门）、location、status |
| 都市 | rank（职位）、wealth（财力）、network（人脉）、company（公司）、location、status |
| 科幻 | rank（军衔）、cyberware（义体等级）、clearance（权限）、ship（舰船）、location、status |
| 悬疑 | suspicion（嫌疑度）、motive（动机）、alibi（不在场证明）、location、status |
| 言情 | affection（好感度）、stage（关系阶段）、misunderstanding（误会）、location、status |
| 自定义 | 由你自己填写 |

切换预设时会自动填入对应的提示文本；你也可以在文本框里直接改写。注入层会**遍历角色 `state` 下的所有字段**，不只 `realm/technique/location/status`，所以临时新增 `rank`、`suspicion` 等字段也会显示。

每个预设还带 `fieldLabels` 和 `panelMap`：

- `fieldLabels`：状态栏显示的中文标签（境界、名望、性别、外貌……）；
- `panelMap`：字段归到「状态」还是「个人状态」；
- 文字冒险常用字段：`objective`（目标）、`situation`（局势）、`fame`（名望）、`health`（伤势/状态）。

> 题材预设只影响“提取时用什么字段名、状态栏怎么显示”；文笔风格仍由世界书/系统提示决定，本插件不干预。

### 金钱与物品数量

物品支持 `quantity` / `unit` / `kind`：

```json
{
  "id": "i_spirit",
  "name": "灵石",
  "kind": "currency",
  "quantity": 120,
  "unit": "枚",
  "holder": "lin_yuan",
  "validTo": null
}
```

- `kind: "currency"` 表示货币；状态栏会把它汇总到「资产」。
- `kind: "consumable"` 表示丹药/符箓/子弹等消耗品。
- `kind: "equipment"` / `"item"` 表示装备和普通物品。

数量变化用 `adjust_item`：

```json
{ "op": "adjust_item", "item": "i_spirit", "delta": -30, "reason": "购买回气丹", "evidence": "msg:88", "confidence": 0.95 }
```

- `delta` 正数 = 获得，负数 = 消耗；
- 每次变化写入 `quantityHistory`（before/after/delta/reason/evidence）；
- 数量不会降到负数，最低为 0；
- 给另一个角色加钱时，可写 `character` + `itemName` + `unit`，不存在会自动创建。

失去物品/金钱的专用操作：

| op | 用途 |
|---|---|
| `remove_item` | 失去某一件物品，关闭当前记录 |
| `clear_items` | 失去某一类/全部非货币物品；`includeCurrency: true` 连钱一起清 |
| `clear_currency` | 失去所有金钱，数量归零 |
| `set_item_quantity` | 精确设置数量（“只剩三颗”“正好 100 灵石”） |

```json
{ "op": "clear_items", "character": "lin_yuan", "kinds": ["equipment", "consumable"], "reason": "被洗劫" }
{ "op": "clear_currency", "character": "lin_yuan", "reason": "灵石被抢" }
{ "op": "set_item_quantity", "item": "i_spirit", "quantity": 0, "reason": "被盗" }
```

物品在角色间转手用 `move_item`：

```json
{ "op": "move_item", "item": "i_sword", "to": "su_wan", "evidence": "msg:0", "confidence": 0.95 }
```

它会关闭原持有人的记录，并在新持有人名下新建一条当前记录；不要用 `remove_item` + `add_item` 代替。

题材预设自带默认货币：

| 题材 | 货币 |
|---|---|
| 修仙 | 灵石（枚） |
| 都市 | 人民币（元） |
| 科幻 | 信用点（点） |
| 悬疑 / 言情 | 现金（元） |

### 可视化知情者编辑器

「认知」页只列出**主角自己拥有的秘密**。每张卡片都有「编辑档位」按钮：

- 给条目选一个档位：主角级 / 亲密级 / 朋友级 / 公开级；
- 卡片上直接显示当前档位与「够格的人」；
- 猜疑/误信写在 `beliefs` 里（编辑 JSON）；
- 保存后立即更新注入。

支持编辑：顶层事实、主角字段、主角物品、主角关系、主角功法、主角神通、主角个人事实。
NPC 自身的性别、境界、身份、关系、状态不做隔离，因此不会出现在这里。

### 提取模型建议

**实测结论：9B 级模型只能应付短对话，长对话会漏掉秘密对象或生成大量噪声。建议直接用 27B 级模型（如 `aifeifei798/Qwen3.8-Queen-27B`）做提取。**

- 能稳定输出 JSON（不会夹杂解说或 Markdown）；
- 上下文 ≥ 32K；
- 27B 级实测：4 条对话 4 条 op、20 条对话 10 条 op，秘密对象与知情档位均正确；
- 9B 实测：短对话可用；20 条对话出现漏记秘密、5 万字符噪声 JSON 截断、偶发超时；
- 扩展会向提取请求附加 `response_format: {"type":"json_object"}`；若服务端不支持，会自动去掉并重试一次；
- 非思考型优先；如果是思考型，把「提取最大 token」提高到 8192；
- 若主模型在 Featherless 上频繁 `capacity_exhausted`，可勾选「跟随当前连接」，或另配一个提取专用 profile。

#### 破限提示词：不需要

2026-10-23 用 DZMM 导出的 NSFW 段落实测（`deepseek-flash`，S1 SFW + S2/S3 NSFW × 无破限 / system 前缀 / user 前缀，共 9 次）：

- **9/9 返回合法 JSON，0 次拒绝，0 次空正文；单轮 2.5–4.4 秒。**
- 破限块放 system prompt 前面：无收益，也没有降质。
- 破限块放 user 消息前面：SFW 场景漏记“外貌体型”，会分散模型对原提取规则的注意力。
- 结论：提取是“数据整理”，不是“创作”，DeepSeek-flash 不会因为正文是 NSFW 就拒绝。**不要为提取加破限提示词**；如果以后换模型确实需要，只做 system 前缀的可选开关，默认关闭，不要注入 user 消息。

## 5. 使用

1. 选择提取连接（或勾选「跟随当前连接」）。
2. 正常聊天。
3. 每收到一条 AI 回复就自动结算一次：只提取 `lastProcessedMessage` 之后的新消息，并额外带前 3 条作上下文；也可点「结算本幕」手动结算。
4. 打开「事实台账」面板：
   - **角色**：角色状态与物品
   - **认知**：主角的秘密与谁知情
   - **日志**：版本日志与回放
   - **健康**：注入估算、泄露、健康告警、注入预览
5. 需要手工修正时，点「编辑 JSON」直接改完整台账。
6. 定期用「导出 JSON」备份。

## 8. 排错

### `... is temporarily at capacity. Please try again shortly.`

Featherless 的**模型容量不足**，语义上对应官方文档的 503（不是 429 账户并发超限）。

实测细节：

- HTTP 状态可能是 **200**，错误放在响应体：
  ```json
  { "error": { "type": "server_error", "code": "capacity_exhausted", "message": "... is temporarily at capacity." } }
  ```
- 没有 `Retry-After` 或 rate-limit 头；
- 按模型区分：同一时刻 Queen 可能可用，其他模型仍满负荷。

扩展会自动重试 2 次（每次 8 秒），仍失败才报真实错误。可改用「跟随当前连接」或另一个提取 profile。

### 提取返回空内容

多为思考型模型把 max token 用在了 reasoning 上。把「提取最大 token」提高到 4096–8192，或换非思考模型。

### 注入没有出现在生成里

- 确认「启用台账」为开；
- 确认当前有聊天（`chatId` 不为空）；
- 打开「健康」页看「注入估算」是否大于 0；
- 检查是否有其他扩展覆盖了同名 `setExtensionPrompt` key（本扩展使用 `factledger`）。

### 需要排查时：复制调试信息

打开「事实台账」→「健康」→「复制调试信息」。它会复制一份紧凑 JSON 并输出到浏览器控制台：

- 聊天条数、`lastProcessedMessage`、`lastProcessedHash`；
- 版本日志条数与最近 20 个回放点；
- 最后错误、上次结算时间；
- 角色/事实的 ID 列表、场景、泄露数量、注入 tokens；
- 当前提取与注入设置。

不包含物品或事实的正文，只有 ID 与计数。排查时把这段 JSON 和 `[FactLedger]` 开头的控制台日志一起提供即可。

### 调试命令（斜杠命令）

在聊天输入框直接运行：

| 命令 | 作用 |
|---|---|
| `/factledger-status` | 打开调试弹窗：聊天长度、回放点、版本日志、错误、设置 |
| `/factledger-history` | 查看版本日志的全部回放点 |
| `/factledger-settle` | 立即结算 |
| `/factledger-replay <序号>` | 把台账回放到该聊天序号对应的版本（不修改聊天内容） |

别名：`/fl-status`、`/fl-history`、`/fl-settle`、`/fl-replay`。

调试弹窗里有一段只读 JSON，可直接选中复制；剪贴板不可用时也会自动打开这个窗口。

### 角色知道了不该知道的事

- 检查秘密条目的档位是否设得太低（例如把只有主角知道的事写成了 `public`）；
- 在「健康」页点「检查最近回复」看启发式候选；
- 提取模型返回的 `leaks` 更准确，结算后会自动显示。

## 9. 已知限制

- 提取质量依赖所选模型；JSON 遵循度差的模型会频繁被规则层拒绝。
- 9B 级提取模型在 20 条以上对话中会漏记秘密对象或生成大量噪声，实测建议使用 27B 级（如 Queen）。
- 秘密知情约束是「结构注入 + 提示约束 + 泄露检测」三层组合，不能保证模型 100% 不泄露。
- 启发式泄露检测基于中文 2–4 字 n-gram，可能误报；以提取模型的 `leaks` 为准。
- `narrator_only` / `faction` 已并入档位模型：前者等同主角级，后者不再单独支持。
- 旧数据加载时会自动把 `chapter` 映射为 `time` 并删除 `chapter`；NPC 的当前物品会转为个人事实，`items` / `relations` 清空；NPC 自身信息上的 `visibility` / `knownBy` / `access` 会被清除（信息值保留）。
- 斜杠命令（`/factledger-status` 等）需要 SillyTavern 1.19+；面板按钮不受影响。
- 台账保存在当前聊天的 `chatMetadata` 中，换聊天不会共享；跨聊天请用导出/导入。

## 10. 隐私与数据

- 台账只保存在本地 SillyTavern 的聊天 metadata 与导出的 JSON 中；
- 提取调用会把「最近对话 + 当前台账」发送给你选择的 API（如 Featherless）；
- API Key 由 SillyTavern 的 secrets 管理，扩展不读取、不落盘明文；
- 建议定期导出 JSON 备份，尤其是在大规模改写剧情前。
